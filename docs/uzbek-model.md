# Узбекская модель общих тем

Модель `uzbek-topics-1.0` обучается локально на CPU и сохраняется в
`backend/models/ml_classifier.joblib`. API подхватывает её после перезапуска.
Реальные данные и бинарная модель остаются локальными и исключены из Git;
скрипты, этот документ и JSON-отчёт позволяют проверить и повторить обучение.

## Источник и темы

Используется [Uzbek Zero-Shot Classification Dataset](https://huggingface.co/datasets/risqaliyevds/uzbek-zero-shot-classification)
автора Riskaliev Murad: 96 970 новостных текстов. Несмотря на название набора,
здесь он используется для обучения классификатора с размеченными примерами.
Зафиксирована ревизия `a4ad4607a7c1ffe492fe1420a05fb6c7b6165383`.
Карточка автора указывает MIT. Исходные статьи происходят с новостных сайтов;
права на каждую статью отдельно не проверены. Набор не публикуется повторно.
Локальная карточка и SHA-256 находятся в `backend/data/uzbek_public/`.

## Результат первого обучения

После очистки осталось 96 785 текстов: 77 428 для обучения, 9 678 для
калибровки, 9 679 для теста. Удалено 20 строк с противоречивыми метками
и 165 дублей/одинаковых начал. Обучение заняло около 7 минут; артефакт — 18 МБ.

| Метрика на отдельном тесте | Значение |
| --- | --- |
| Accuracy | 84,47% |
| Macro F1 | 0,819 |
| Weighted F1 | 0,845 |
| Log loss | 0,417 |
| Accuracy постоянного прогноза самого частого класса | 30,48% |

Лучший F1 у спорта (0,976); слабее различаются мировые новости (0,728),
культура (0,733) и общество (0,757). Эти числа относятся к этому тестовому
набору и не измеряют качество на документах пользователя.

После подключения проверены настоящий API, загрузка/классификация/скачивание
текста, PDF и DOCX, совпадение вероятностей для эквивалентных фраз на латинице
и кириллице. В интерфейсе создан явно помеченный пример про образование на
кириллице; модель определила `Ta'lim`. Это функциональная проверка, а не
дополнительная оценка качества.

## Повторить обучение

В каталоге `backend`, в активированном окружении Python 3.12:

```powershell
python -m pip install -r requirements-uzbek.txt
python -m ml.collect_uzbek
python -m unittest discover -s tests -v
python -m ml.train_uzbek
```

Для работы API дополнительно нужны серверные зависимости проекта из
`requirements.txt`. CPU trainer не требует Torch или Transformers.
Загрузка доступна без аккаунта и токена, скрипт не исполняет код источника.

Pipeline: нормализация письменности → TF-IDF слов (1–2) и фрагментов слов
(3–5) → LinearSVC → sigmoid-калибровка вероятностей. Словарь признаков и
классификатор обучаются только на 80% очищенного набора. Калибровка использует
отдельные 10%, тест — оставшиеся 10%. Seed = 42. После проверки тест не
добавляется обратно в обучение, чтобы метрики соответствовали сохранённой модели.

Убираются пропуски, тексты короче восьми слов, дубли нормализованного текста
и статьи с одинаковыми первыми 40 словами. Группы одинаковых начал с
противоречивыми метками удаляются полностью. Это не гарантирует удаления
всех пересказов одной новости. Разбиение случайное и стратифицированное;
проверка на другом источнике или более поздних данных пока не проводилась.

В `backend/data/uzbek_public/` сохраняются `train.csv.gz`,
`calibration.csv.gz`, `test.csv.gz` и `split-manifest.csv` с хешами документов.
В [uzbek-model-report.json](uzbek-model-report.json) сохраняются размеры
выборок, точность, macro/weighted F1, log loss, метрики по темам, матрица
ошибок, версии библиотек и SHA-256 модели. Строки матрицы — истинные метки,
столбцы — предсказанные; порядок указан в `labels`.

## Письменность и границы применения

Латиница и кириллица приводятся к общему латинскому представлению одинаково
при обучении и при обращении к API. Это транслитерация, а не перевод.
Результаты проверены на латинском новостном корпусе; независимого размеченного
корпуса естественных кириллических текстов нет. Тесты эквивалентных фраз
проверяют преобразование, но не измеряют качество на всей кириллице.

Модель определяет одну наиболее вероятную общую тему. Она всегда выбирает
из десяти тем: класса «Другое» и отдельного детектора неизвестных тем нет.
Короткие, смешанные и непохожие на новости документы могут давать ненадёжные
результаты. Для канцелярских документов, учебных материалов и внутренних
отчётов нужна отдельная размеченная проверка и, при необходимости, дообучение.
PDF со сканами без текстового слоя по-прежнему требует OCR.

Статус и метрики подключённой модели доступны в `GET /ml/status`
и в разделе «Модели» дашборда. Чтобы загрузить другую модель, задайте
`ML_MODEL_PATH`; при наличии transformer-каталога он имеет приоритет над
стандартным joblib-путём. Старые sklearn-модели продолжают использовать
свою прежнюю нормализацию.
