# Архивный анализ

Экспериментальный метод `structural`, версия `archive-1.0`. Использует категории и ключи из выбранной SQLite-базы. Базовый словарный метод остаётся доступным для сравнения.

Текст делится по абзацам. Первые три непустых строки, не более 160 слов, считаются заголовком. После отдельной метки `ILOVA` / `ИЛОВА` начинается приложение. Остальной текст — основная часть. Упоминание `1-ilovaga muvofiq` внутри предложения не переключает зону. Форматирование PDF, необычные заголовки и расположенные в начале таблицы могут нарушать эту эвристику.

В каждой зоне ищутся узбекские фразы с общей нормализацией латиницы и кириллицы и ограниченными правилами окончаний. В заголовке фраза может пересекать соседние строки; в основном тексте и приложениях — только один абзац.

## Расчёт

Для ключа `k` в категории `c`:

```text
base(k,c) = percent × weight
importance = base / max(base в категории)
specificity = 1 + log2((число категорий + 1) / (число категорий с этим ключом + 1))
phrase = sqrt(min(4, число слов ключа))
size = sqrt(число разных ключей с положительным весом в категории)
score(k,c) = importance × specificity × phrase / size
             × [3 × log2(1 + n_header) + log2(1 + n_body) + 0.25 × log2(1 + n_appendix)]
```

Сумма вкладов ключей задаёт балл категории. Дубли одинакового нормализованного ключа внутри категории учитываются один раз с максимальным исходным весом. Общие ключи влияют слабее характерных; повторения имеют убывающий вклад. Нормализация по размеру словаря снижает преимущество папок с большим числом ключей.

Это проектная эвристика с явно выбранными параметрами, а не новый математический метод с доказанной научной новизной. TF-насыщение, взвешивание зон и нормализация словарей имеют аналоги в поиске и классификации. Коэффициенты не оптимизировались на размеченном наборе архивных документов. Численно сравнивать баллы этого метода с обычным словарём нельзя.

Ручная проверка предлагается при отсутствии совпадений, менее двух разных ключей победителя, отсутствии характерного ключа в заголовке или разнице долей двух ведущих категорий менее 10 процентных пунктов. Отсутствие этой метки не гарантирует правильность.

Результат содержит вклад каждого ключа по зонам и фрагменты нормализованного текста вокруг совпадений. Итоговая доля — отношение балла победителя к сумме баллов всех папок; это не вероятность.

## Проверки

Тесты охватывают повторяющееся приложение, одинаковые оценки, неизвестный текст, дубли ключей, изменение масштаба весов категории, обе письменности, фразы через строки заголовка и запрет фраз через разные абзацы тела. Это контролируемые примеры, а не независимый корпус оценки качества.

На реальном `farmoni.docx` с базой учительницы выбранная папка — 1. Подробный ответ API и контрольные суммы сохранены в [archive-example-test.json](archive-example-test.json). Для общей оценки нужны размеченные документы всех четырёх папок, сравнение с базовым методом и отдельная тестовая выборка.

Существующая новостная ML-модель не изменялась: общая тема и архивная папка остаются разными задачами.
