# Проверка происхождения проекта перед диссертацией

Дата: 8 октября 2026 года. Вуз по информации пользователя: ТУИТ. Название проверяющей системы, порог оригинальности, программа обучения и правила использования ИИ неизвестны.

## Заключение

Проведён локальный аудит происхождения файлов, истории Git, зависимостей, корпуса и модели. **Официальной проверки антиплагиатом не было; процент оригинальности не установлен.** Сопоставление всех исходников с внешними репозиториями и закрытыми базами не выполнялось. Текст диссертации не предоставлен.

Проект имеет существующую основу с несколькими авторами, использует сторонние библиотеки, внешний корпус и доработки с помощью ИИ. Утверждение «весь код, данные и алгоритм самостоятельно созданы автором диссертации» имеющимися материалами не подтверждается. Это не устанавливает факт нарушения: необходимо выяснить реальное участие автора и корректно обозначить источники.

Публичная [страница ТУИТ о магистратуре](https://tuit.uz/magistratura) упоминает плагиат, фальсификацию данных и ложные цитаты как нарушения. Она не устанавливает в рамках этой проверки используемый сервис, порог или применимость к конкретной программе пользователя. Найденные сведения не заменяют актуальные правила кафедры.

## Что проверено

- Перечень отслеживаемых и неигнорируемых файлов проекта, SHA-256 и сравнение с локальным HEAD `504e3de` с нормализацией переводов строк.
- История авторов Git и корневая MIT-лицензия с уведомлением `Copyright (c) 2025 Ganijon`.
- Прямые frontend-зависимости и лицензии всех 267 записей зависимостей npm lockfile.
- Объявленные Python-зависимости и метаданные установленных пакетов. Часть пакетов отсутствует; метаданные не заменяют полный юридический анализ лицензий.
- Источник, ревизия и локальная карточка новостного корпуса; контрольная сумма текущей sklearn-модели совпадает с отчётом обучения.
- Исходники альтернативного transformer workflow и ноутбук: ноутбук не содержит сохранённых результатов выполнения.
- Документация результатов и ограничений, сторонние ресурсы интерфейса и происхождение присланных учительницей данных.

Не включены в перечень авторских исходников `node_modules`, виртуальные окружения, сборка `dist`, полный корпус и загруженные пользовательские документы. Это отделяет предмет разработки от внешних материалов; если вуз требует весь архив, эти материалы нужно описать в сопроводительном реестре, а не скрывать.

## Основные риски и необходимые действия

| Наблюдение | Как подготовить работу |
| --- | --- |
| Git содержит несколько имён авторов; часть исходников сохраняется с прежней версии | Указать исходный проект и точно описать участие студента. Имена Git могут быть псевдонимами одного человека; это нужно подтвердить, а не предполагать. |
| MIT-лицензия содержит имя Ganijon | Сохранить уведомление. Свободная лицензия не заменяет академическую атрибуцию. Не менять авторство ради совпадения с титульным листом. |
| Корпус скачан с Hugging Face | Указать составителя, ссылку, ревизию, способ получения и очистки. Не писать «собран собственный корпус из 96 970 статей», если имеется в виду скачивание готового набора. |
| TF-IDF, SVM и sigmoid-калибровка реализованы scikit-learn | Ссылаться на методы и библиотеку. Корректная характеристика — адаптация и исследование существующего pipeline, а не изобретение SVM или TF-IDF. |
| Изменения создавались с помощью Codex | Описать помощь ИИ и фактические действия автора работы согласно правилам программы. Локальные изменения не доказывают личное написание всех строк студентом. |
| Словарь четырёх папок предоставлен учительницей | Указать внешний источник категорий, ключей и весов. При включении файла в публичное приложение выяснить авторство и разрешение на распространение. |
| Новостная модель и архивные папки решают разные задачи | Разделить эксперименты. Accuracy 84,47% относится к тесту новостей из десяти тем, не к четырём архивным папкам. |
| Есть только один пример архивного документа | Не заявлять измеренную точность классификации папок. Результат «папка 1» — одна функциональная проверка с ожидаемой категорией, выведенной из содержания. |
| Словарь даёт 48,3% доли баллов | Не называть это вероятностью или точностью. Сохранить описание формулы и совпавших ключей. |
| Альтернативный transformer pipeline присутствует в коде | Не выдавать его за реально выполненное обучение. Для утверждений о transformer-результатах нужны отдельные артефакты, журнал и тестовая выборка. |
| Текущая среда наследует часть системных пакетов; ряд версий отличается от requirements.txt | Для воспроизведения зафиксировать фактическое окружение. Это риск повторяемости, не доказательство плагиата. Версии ключевых библиотек обучения уже записаны в отчёте модели. |

## Как описать имеющиеся результаты

Ниже фактическая заготовка, которую нужно адаптировать к подтверждённому личному вкладу, а не вставлять как заявление о самостоятельном авторстве:

> На основе существующего проекта CuTxT выполнены доработки интерфейса и обработки узбекских документов. Для классификации общих тем использован публичный корпус risqaliyevds/uzbek-zero-shot-classification фиксированной ревизии. Реализован pipeline подготовки данных и обучения с библиотечными TF-IDF, LinearSVC и калибровкой вероятностей. На выделенной тестовой части получены accuracy 84,47% и macro F1 0,819. Эти результаты относятся к новостному корпусу. Для архивной классификации использован предоставленный словарь четырёх папок; исправлено сопоставление письменностей, фраз и окончаний, а также чтение таблиц DOCX. При подготовке кода, тестов и документации использовалась помощь Codex.

В разделе личного вклада добавить только реально выполненные студентом действия. Возможные предметы исследования — сравнение словарного и статистического подходов на подходящих данных, влияние нормализации письменности, ошибок извлечения и конфигурации признаков. Сейчас полноценные сравнительные эксперименты или доказанная научная новизна таких подходов не представлены.

## Подготовка к строгой проверке

1. Получить правила кафедры по заимствованному коду, ИИ и составу проверяемого архива. Название сервиса необязательно для корректной атрибуции.
2. Зафиксировать реальное авторство основы и личный вклад, сохранить Git-историю и лицензии.
3. В тексте диссертации дать ссылки рядом с описанием внешних методов, корпуса, программы и предобученных моделей. Добавить библиографию; ссылки только в README не заменяют ссылки в диссертации.
4. Воспроизвести заявленные эксперименты и сохранить журнал, версии, разбиение и артефакты. Отделить подтверждённые результаты от планируемых исследований.
5. Для оценки четырёх папок подготовить независимый размеченный набор документов всех категорий. Одного примера недостаточно.
6. Проверить окончательный текст и исходники через систему, принятую вузом, и разобрать конкретные совпадения с источниками. До такого отчёта гарантировать прохождение нельзя.

Перестановка строк, переименование переменных, удаление источников или маскировка текста не подтверждают самостоятельность и не являются способом исправления найденных рисков.

Повторить локальную инвентаризацию из корня проекта:

```powershell
& '.\backend\.venv\Scripts\python.exe' -X utf8 scripts/audit_provenance.py
```

Скрипт ничего не отправляет наружу и не меняет код приложения. Счётчики неизменённых, изменённых и новых файлов описывают отличие от HEAD; они **не измеряют процент оригинальности**.
